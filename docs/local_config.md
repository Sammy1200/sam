# 本机配置边界

本文用于说明哪些配置已经本机外置、示例文件与真实文件的边界，以及哪些本机内容默认不应提交 Git。

---

# 本机换号配置外置

当前主线事实：
- 线程 8 已完成，本机换号配置外置

含义：
- 与本机环境强相关的换号配置，不应继续硬编码成统一真值
- 修改这类内容时，应优先确认是否属于本机配置层，而不是直接改业务主逻辑

当前边界：
- 真实本机换号配置以 `local_switch_account_config.json` 为准
- 示例文件只用于说明字段结构，不代表当前机器真实运行值
- 读取链路由 `local_switch_account_config.py` 承接时，也应继续遵守“真实文件优先、示例文件只做说明”的原则

---

# 本机网页同步 / 远端最小写回配置

当前主线事实：
- 双机网页汇总配置仍由 `local_web_sync_config.json` 承接
- 线程 14 第一阶段新增可选开关 `receive_remote_writeback`

含义：
- `local_web_sync_config.json` 仍属于真实本机配置，不应被示例文件覆盖
- `receive_remote_writeback` 只控制“当前机器是否接受远端最小写回”
- 该能力只用于线程 14 第一阶段定义的 3 个字段，不代表开放任意远端写入口

当前边界：
- 1 号电脑通常负责展示与发起提交，可不开启 `receive_remote_writeback`
- 2 号电脑如需接受来自 1 号电脑的最小写回，应在真实本机 `local_web_sync_config.json` 中显式开启 `receive_remote_writeback`
- 当 `receive_remote_sync` 或 `receive_remote_writeback` 任一开启时，网页服务绑定地址应能被另一台机器访问

# 本机昵称识别区域 / 阈值外置

当前主线事实：
- 线程 13 已完成，本机昵称识别区域与阈值配置外置

含义：
- 本机屏幕差异、窗口差异、识别差异，优先走本机配置层治理
- 不要在没有必要的情况下，把本机识别差异回写成全局硬编码

---

# 示例文件与真实文件边界

处理配置时必须区分两类文件：
- 示例文件：用于说明结构、字段、格式、默认值示意
- 真实文件：用于当前机器实际运行

硬规则：
- 不要用示例文件覆盖真实文件
- 不要把真实本机值误写回示例文件，除非任务明确要求同步示例
- 不要把“为了本机能跑”的临时值直接写成全局默认值
- `local_switch_account_config.json` 是真实本机换号配置文件，不能被示例文件回填覆盖
- 示例文件只负责提供字段示例、格式样例、默认说明，不负责承载真实本机值

---

# 默认不提交 Git 的本机配置

以下内容默认按本机专属处理，不应直接提交 Git，除非用户明确要求：
- 本机换号真实配置
- 本机昵称模板资源
- 本机昵称模板目录配置
- 本机昵称识别区域参数
- 本机昵称识别阈值参数
- 其他明显依赖本机环境差异的真实运行值

对应到当前主线，默认不提交 Git 的真实本机文件 / 内容包括：
- `local_switch_account_config.json`
- 本机昵称模板目录下的真实模板资源
- 本机昵称识别区域真实取值
- 本机昵称匹配阈值真实取值

处理这类文件时，优先目标是：
- 保证当前机器可运行
- 不污染主线通用配置
- 不把本机差异误当成全局规则
