# 网页与同步边界

本文用于收口网页查看能力、最小修改能力、本地网页服务拉起方式，以及双机网页汇总的当前边界。

---

# 网页查看与最小修改能力

当前主线已经具备：
- 网页查看能力
- 单账号最小修改能力

这里的“最小修改”应理解为：
- 以低风险、最小范围为原则的局部网页侧修改
- 不改变主线真源规则
- 不引入双向同步语义

当前网页最小修改只允许以下 3 个字段：
- 道具数量（实际写入 `baseline_item_count`）
- 账号状态（`round_status`）
- 余额（`current_balance`，页面按“万”为单位输入和展示）

不允许通过网页最小修改直接改动：
- 抢购主循环依赖的运行时关键参数
- SQLite 真源统计口径
- 会影响跨机汇总主键判断的昵称主键语义

不要把它表述成：
- 全量网页编辑后台
- 任意远端数据治理入口
- 跨机共享写入口

---

# 本地网页服务自动静默拉起

当前主线事实：
- `main.py` 已具备自动静默拉起网页服务的能力

文档表述边界：
- 这是当前主线能力的一部分
- 目的是降低日常启动成本
- 不代表网页服务脱离主入口独立成为新的正式启动链路

正式启动 / 验收入口仍然只有：
- `.\scripts\register_scheduled_task.ps1`
- `.\古墓迷途.cmd`
- `.\scripts\run_via_task.ps1`

# 双机网页汇总第一阶段

当前已完成范围：
- 双机网页汇总第一阶段
- 2 号电脑只读镜像

正确理解：
- 这是阶段性成果，已经可以视为主线当前能力
- 但仍然属于“第一阶段”，不要写成完整双机同步系统已完成

---

# 线程 14 第一阶段：双机远程最小写回

当前新增能力仅限：
- 从 1 号电脑网页，对 2 号电脑单账号提交最小修改
- 只允许修改 3 个字段：
  - 道具库存（`baseline_item_count`）
  - 账号状态（`round_status`）
  - 余额（`current_balance`，页面按“万”为单位输入）
- 写回目标必须是 2 号电脑本机 canonical SQLite 真源
- 写回成功后必须有成功/失败回执，并立即执行镜像刷新或回读确认

这个能力的正确理解是：
- 页面上的“2号电脑板块”本质上仍然是远端镜像展示区
- 镜像层本身仍然不是真源，也不能直接当作最终写入口
- 真正写入发生在 2 号电脑本机网页服务提供的专用最小写回接口
- 1 号电脑只负责发起请求、接收回执，并用 2 号电脑回传的最新快照刷新镜像显示

---

# 远端镜像边界

当前远端镜像规则：
- 远端镜像不是真源
- SQLite 仍是唯一真实数据源

具体边界如下：
- 远端页面可以查看镜像结果，但不能替代本机 SQLite 作最终判定
- 远端镜像可以承接展示、副本汇总、只读查询，但不能作为最终写入口
- 远端镜像本身不能直接回写本机真实账号库
- 远端镜像不能覆盖本机轮次统计、轻量落库或最终写回结果
- 出现镜像与本机不一致时，以本机 SQLite 真源为准
- 线程 14 第一阶段允许的远端最小写回，必须通过专用接口转发到 2 号电脑本机 canonical 真源，再由真源结果反向刷新镜像

因此文档中必须避免以下错误表述：
- 远端可直接改真源
- 镜像库与本地库地位等同
- 远端页面可作为最终写入来源

---

# 明确不做的事项

当前边界内，明确不做以下能力：
- 双向同步
- 共享 SQLite
- 远端任意字段写回真源
- 远端直接绕过专用接口修改本机主账号数据
- 远端覆盖本机统计与持久化结果

如果后续有新需求，也必须在不破坏以下硬规则的前提下单独评估：
- SQLite 是唯一真实数据源
- 昵称是唯一键
- 远端镜像不是真源
- 不影响抢购主循环
