# 当前主线稳定基线

本文用于说明当前主线已经明确具备的能力边界，避免把阶段成果写大，也避免把“已合并”误写成“绝对不可动”。

---

# 基线事实

当前主线应被视为已经具备以下稳定能力：
- 正式入口固定为：
  - `.\scripts\register_scheduled_task.ps1`
  - `.\古墓迷途.cmd`
  - `.\scripts\run_via_task.ps1`
- 抢购、上架、换号/换区、悬浮窗显示仍是主线能力范围
- 不影响抢购主循环仍是最高优先级
- SQLite 仍是唯一真实数据源
- 昵称仍是唯一键
- 56 分钟轻量落库规则仍然有效
- 2 小时 50 分统计口径仍限定在真正抢购循环活跃态
- 远端镜像仍不是数据真源

# 只算阶段完成，不要误写成完整系统完成

以下表述需要克制，不要扩大：
- “线程 2 已完成”不等于所有统计指标都可以任意改口径
- “线程 3 已完成”不等于所有读取链路都可以脱离既有冷却与等待规则重写
- “线程 4 第一批已完成”不等于悬浮窗整体改造已全部完成
- “线程 5 已完成”不等于持久化链路后续不可调整
- “线程 7 当前阶段已完成”不等于网页系统后续所有阶段都已完成
- “线程 12 第一阶段已完成”不等于双机协同、远端数据治理、同步体系已完整完成
- “本机配置外置已完成”不等于所有环境差异治理都已经结束
- “临时抢购模式已完成”不等于所有抢购模式都已经封板

# 已合并，但不应写成绝对稳定不可动

以下内容虽然已经合并进主线，但不应被文档写成“绝对稳定不可动”，正确表述应是“当前规则有效，后续如有明确需求可谨慎演进”：
- 统计口径统一后的统计展示与汇总方式
- 账号读取、冷却判断、等待逻辑的外围实现
- 悬浮窗正常模式纯显示增强
- 轻量落库与最终写回实现
- 网页查看能力与单账号最小修改能力
- 本机换号配置外置
- 本机昵称模板资源 / 区域 / 阈值外置
- 双机网页汇总第一阶段
- 2 号电脑只读镜像
- 临时抢购模式

这些能力的共同边界是：
- 可以在明确需求下继续优化
- 但任何后续调整都不能破坏当前主线硬规则
- 尤其不能影响抢购主循环、真源边界、统计口径和落库节奏
