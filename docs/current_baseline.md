本文用于说明当前主线已经明确具备的能力边界，避免把阶段成果写大，也避免把“已合并”误写成“绝对不可动”。

# 基线事实

当前主线应被视为已经具备以下稳定能力：
- 正式入口固定为：
  - `.\scripts\register_scheduled_task.ps1`
  - `.\古墓迷途.cmd`
  - `.\scripts\run_via_task.ps1`
- 启动器当前已支持六种入口：
  - 登录界面启动
  - 启动页上架模式
  - 临时抢购模式
  - 暴力模式
  - 饰品抢购模式
  - 装备抢购模式
- 启动器有 `功能设置` 按钮，会打开 `参数设置` 弹窗；`全局设置` 里的 `启用上架` 保存到 `C:\py666\local_switch_account_config.json`，关闭后“上架模式”不可点击，本次启动内所有账户都会跳过上架操作，包括首次预上架、换号后预上架和 10 分钟循环上架
- `参数设置` 的 `石头设置` 支持两种石头抢购方式：`前缀抢购` 保持现有前缀规则，`固定上下限抢购` 只按含等于的石头价格上下限判断
- `参数设置` 的 `装备设置` 支持设置装备抢购价格上下限，默认仍等价于 `50000 < 价格 < 4200000`
- 暴力模式从交易行页面启动，不上架、不换号、不入库、不写每日统计；交易行正常时先刷新进入道具详情页，详情页未命中 `meihuo.png` 才直接执行 `购买 -> 确定`
- 饰品抢购模式绑定正常账号身份链路，全程不上架；换号/切区沿用正常链路，切换后进入饰品交易行继续饰品循环；饰品运行数据写入独立饰品库 `C:\py666\accessory_account_stats.sqlite3`，正常石头库继续使用 `C:\py666\account_stats.sqlite3`
- 装备抢购模式绑定正常账号身份链路，全程不上架；进入装备详情页并完成筛选保存后，使用第二价格区和数字模板循环抢购；装备价格识别不使用正常模式颜色守卫，不新增装备独立 SQLite
- 启动器选择模式后，会先隐藏大悬浮窗并确认完成，再进入后续启动页识别和点击链路
- F9 计数悬浮窗可在启动器未选择模式阶段或 F12 暂停态使用；启动器选择任意模式前会先关闭计数窗，关闭后计数窗销毁并停止截图扫描，F12 恢复前会先关闭计数窗；计数窗打开期间小键盘 `+` 可启动“快速交易”，执行中再次按小键盘 `+` 会取消本次快速交易任务
- 普通上架提交验证失败后，会先治理首次提示弹窗；弹窗消除成功即按上架成功处理，未命中再补点提交按钮并做局部场景恢复；全场景识别已能识别上架页面
- 抢购、上架、换号/换区、悬浮窗显示仍是主线能力范围
- 不影响抢购主循环仍是最高优先级
- SQLite 仍是唯一真实数据源
- 昵称仍是唯一键
- 石头道具 72 小时不可交易库存的数据模型与核心入库口径第一阶段完成：石头库保留兼容总库存 `baseline_item_count`，并新增 `locked_item_count`、`tradable_item_count`、`next_tradable_at` 和 pending 批次表；旧库存迁移到可交易库存，新抢购成功进入不可交易库存并生成 72 小时 pending 批次；普通上架只扣可交易库存，启动页上架模式在游戏已验证上架成功时可扣最近到期的不可交易 pending
- 石头道具 72 小时不可交易库存的网页展示与手动修改第二阶段完成，待统一实机验收：石头库网页按“不可交易 + 可交易 = 总库存”展示和保存，手动增加不可交易会生成 72 小时 pending 批次，手动减少不可交易会按最近到期优先把 pending 批次改为 `cancelled`
- 饰品库继续旧库存逻辑，不启用石头 72 小时不可交易库存拆分
- 56 分钟轻量落库规则仍然有效
- 2 小时 40 分统计口径仍限定在真正抢购循环活跃态
- 远端镜像仍不是数据真源
- `已准备` 已是正式状态值，不是显示映射；当前写入 SQLite 真源与网页状态下拉

# 只算阶段完成，不要误写成完整系统完成

以下表述需要克制，不要扩大：
- “线程 2 已完成”不等于所有统计指标都可以任意改口径
- “线程 3 已完成”不等于所有读取链路都可以脱离既有冷却与等待规则重写
- “线程 4 第一批已完成”不等于悬浮窗整体改造已全部完成
- “线程 5 已完成”不等于持久化链路后续不可调整
- “线程 7 当前阶段已完成”不等于网页系统后续所有阶段都已完成
- “线程 12 第一阶段已完成”不等于多机协同、远端数据治理、同步体系已完整完成
- “线程 14 第一阶段已完成”不等于远端已经成为通用写入口，更不等于共享 SQLite 或双向同步已完成
- “石头道具 72 小时不可交易库存第一阶段 + 第二阶段完成”不等于完整库存系统已全部完成；当前仍待统一实机验收，且不代表后续所有库存治理能力都已完成
- “本机配置外置已完成”不等于所有环境差异治理都已经结束
- “临时抢购模式已完成”不等于所有抢购模式都已经封板

# 已合并，但不应写成绝对稳定不可动

以下内容虽然已经合并进主线，但不应被文档写成“绝对稳定不可动”，正确表述应是“当前规则有效，后续如有明确需求可谨慎演进”：
- 统计口径统一后的统计展示与汇总方式
- 账号读取、冷却判断、等待逻辑的外围实现
- 悬浮窗正常模式纯显示增强
- 轻量落库与最终写回实现
- 网页查看能力与单账号最小修改能力
- 查看页和公网页支持 `石头库 / 饰品库` 切换；本机查看页切到哪个库就按同一套最小保存逻辑写哪个库，公网仍只开放查看与刷新
- 本机换号配置外置
- 本机昵称模板资源 / 区域 / 阈值外置
- 本机 live 数据与本机配置主入口已统一收口到 `C:\py666`，缺失时才回退项目根目录
- 多机网页汇总第一阶段
- 远端电脑只读镜像，当前 1 号电脑预置显示 2/3/4 号电脑
- 多机网页汇总与公网快照的当前正式边界：公网只用于查看，并且只开放刷新按钮，不开放其他修改
- 临时抢购模式

这些能力的共同边界是：
- 可以在明确需求下继续优化
- 但任何后续调整都不能破坏当前主线硬规则
- 尤其不能影响抢购主循环、真源边界、统计口径和落库节奏
