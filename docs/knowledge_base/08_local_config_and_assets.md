# 本机配置、模板资源与 live 数据目录

这份文档用于解释哪些配置已经外置到本机、哪些资源默认只读、哪些目录是 live 数据目录，以及为什么不同电脑必须和主线代码解耦。

## 当前 live 数据目录

当前统一 live 根目录是：

- `C:\py666`

优先从这里读取的内容包括：

- `account_stats.sqlite3`
- `local_switch_account_config.json`
- `local_web_sync_config.json`
- `nichen`

这条规则的目标是：

- 更新代码目录时，只替换代码
- 不把真实运行数据绑死在某一个 worktree 里
- 降低不同仓库目录切换时的运维成本

因此当前网页查看层和本机运行时，都应按“live 路径与代码目录已经解耦”来理解，而不是默认从当前 worktree 目录直接取真值。

## `local_switch_account_config.*`

本机换号配置当前由 `local_switch_account_config.py` 统一读取。

真实文件和示例文件的角色必须分开：

- `local_switch_account_config.json`：真实本机配置
- `local_switch_account_config.example.json`：字段结构示例

示例文件的作用只是说明格式，不是当前机器真实值。

## 本机昵称模板目录与识别参数

当前昵称相关的本机差异已经外置，至少包括：

- 模板目录
- 昵称识别区域
- 昵称匹配阈值

对应到真实本机配置，常见键位是：

- `nickname_template_dir`
- `nickname_verify_region`
- `nickname_match_threshold`

当前优先级是：

1. `C:\py666\nichen`
2. 真实本机配置里的 `nickname_template_dir`
3. 项目根目录默认模板目录

这些配置的作用是：

- 允许不同电脑使用不同模板目录
- 允许不同电脑按各自屏幕与窗口情况设置识别区域
- 允许不同电脑使用各自匹配阈值

它们属于本机配置与资源解耦，不改变线程 6 里“执行位 -> 账号 / 大区”的业务映射本身。

## 本机网页同步配置

网页同步与镜像相关的本机开关由 `local_web_sync_config.json` 承接。这里控制的是：

- 当前机器是否开启同步导出
- 是否接收远端同步
- 是否接收远端最小写回
- 网页服务绑定地址

这些都属于“本机部署差异”，不应直接写死在通用主逻辑里。

## 哪些资源默认只读

当前默认只读的资源包括：

- `logo/` 下模板资源
- `backup_original.py.py`
- 本机真实模板资源目录中的现成模板

除非用户明确要求，否则不要把“为了某次实验能跑”直接扩散成资源替换。

## 本机真实配置与 Git 的边界

默认不应提交 Git 的内容包括：

- 真实本机换号配置
- 真实本机网页同步配置
- 真实本机昵称模板资源
- 真实本机昵称识别区域与阈值
- 运行态产物和本机数据库

这里的原则是：

- 保证机器可运行
- 不污染主线通用配置
- 不把环境差异误写成系统规则

## 为什么必须把本机配置与模板解耦

因为不同电脑之间通常会有以下差异：

- 分辨率和缩放
- 窗口位置
- 模板截图差异
- 局域网同步部署方式

如果这些差异不外置，就会不断把“某台机器能跑”的修补误写进主线。
