# 模块地图

这份文档用于回答“这个项目里每个核心模块到底负责什么”。写法按三个问题展开：负责什么、不负责什么、改它要小心什么。

## `main.py`

- 负责什么：唯一代码入口；管理员权限处理；启动链路衔接；资源加载；模式选择；网页服务静默拉起；上架总开关、暴力模式、饰品模式与装备模式落到运行态；预上架、抢购、切换链的总调度。
- 不负责什么：不承载底层键鼠实现，不直接实现 OCR，也不应该塞入大量展示逻辑。
- 改它要小心什么：不要破坏计划任务启动链；不要改坏“换号后按上架总开关决定是否先上架再抢购”；不要绕开 canonical 读写和最终写回。

## `purchase.py`

- 负责什么：抢购主循环、暴力抢购循环、饰品抢购分流、价格判定衔接、余额识别使用、限制检测、成功/失败计数、切换触发。
- 不负责什么：不负责换号主链、不负责网页展示、不负责 canonical 表结构定义。
- 改它要小心什么：这是最高敏感区；不要随意改正常核心循环结构、检测区域、匹配阈值、关键时序常量；暴力模式必须隔离入库和换号链路；饰品模式不得复用正常价格规则；装备模式必须走装备专用循环，不使用正常模式颜色守卫。

## `listing.py`

- 负责什么：自动上架流程、容量读取、弹窗处理、价格输入校验、上架成功后的库存/余额最小同步。
- 不负责什么：不负责账号切换，不负责网页层渲染，也不负责定义 canonical 状态枚举。
- 改它要小心什么：换号后首次上架要先看启动器上架总开关；上架前余额门槛和周期上架停用规则不能误改。

## `switch.py`

- 负责什么：启动器进入游戏、切区、换号、昵称模板校验、返回古墓大厅、饰品交易行进场、装备详情页与筛选进场、失败治理。
- 不负责什么：不负责抢购主循环本身，不负责数据库表结构。
- 改它要小心什么：步骤顺序很敏感；关键失败出口统一走暂停/推送；换号成功后正常模式必须衔接预上架，饰品模式必须跳过预上架并进入饰品交易行，装备模式必须跳过预上架并完成装备筛选和详情页刷新。

## `account_db.py`

- 负责什么：canonical SQLite 的发现、初始化、表结构、字段归一、状态归一、账号读写、运行态快照表读写、机器级汇总表读写，以及石头库/饰品库的数据源隔离。
- 不负责什么：不负责悬浮窗展示，不负责网页 HTML 生成，不负责实际点击流程。
- 改它要小心什么：`nickname` 是主键；`account_stats` 是 canonical 表；旧规则清理、状态归一、最小字段更新都在这里收口。

## `round_persistence.py`

- 负责什么：轮次运行窗口、56 分钟轻量落库、最终写回、饰品模式复用正常写库但写入饰品库、暂停/恢复快照、机器级汇总、运行时间窗口恢复。
- 不负责什么：不负责页面渲染，不负责实际换号点击。
- 改它要小心什么：这里控制 2 小时 40 分和 24 小时窗口语义；不要把临时模式误写入 canonical；不要把静态展示逻辑混进来。

## `overlay.py`

- 负责什么：悬浮窗创建、计分板显示、日志显示、F12 暂停/恢复、F9 暂停态计数窗呼出、Mini/恢复显示切换。
- 不负责什么：不负责业务决策，不负责数据库结构，不负责复杂识别逻辑。
- 改它要小心什么：正常模式必须保留计分板和日志区；Mini 只能隐藏不能销毁组件。

## `jishujiaoben/`

- 负责什么：F9 计数悬浮窗及其图片资源，可在启动器未选择模式阶段由 `launcher_gui.py` 呼出，或在 F12 暂停态由 `overlay.py` 呼出。
- 不负责什么：不负责主脚本暂停/恢复决策，不负责抢购主循环，不写入账号库。
- 改它要小心什么：关闭计数窗必须停止截图扫描；正常运行态不能启动计数扫描。

## `state.py`

- 负责什么：所有全局可变状态变量。
- 不负责什么：不负责函数、不负责业务逻辑、不负责数据持久化。
- 改它要小心什么：这里只能定义状态；新增状态前先确认是否真的需要全局共享。

## `config.py`

- 负责什么：所有常量、坐标、区域、阈值、等待时间、路径配置。
- 不负责什么：不负责业务逻辑，不负责函数，不导入 `os` 以外模块。
- 改它要小心什么：很多常量直接影响抢购、切换、上架和 live 路径；高敏感参数不能随意动。

## `utils.py`

- 负责什么：底层键鼠、等待、剪贴板、日志器、推送、悬浮窗通用辅助。
- 不负责什么：不负责业务流程编排，不负责 canonical 规则定义。
- 改它要小心什么：这是多模块共用基础层；改动容易产生连锁影响，尤其是输入、等待、日志格式。

## `vision.py`

- 负责什么：截图裁剪、模板匹配、OCR、余额识别、容量识别。
- 不负责什么：不负责数据库写回，不负责换号流程编排。
- 改它要小心什么：识别策略会直接影响抢购和上架；模板目录默认只读。

## `account_view_repo.py`

- 负责什么：canonical 账号数据读取、runtime 辅助快照读取、`临时号` 只读合成行、网页展示字段拼装、石头库/饰品库切换、单账号最小写入与回读校验。
- 不负责什么：不负责 HTTP 路由，不负责页面样式本身。
- 改它要小心什么：网页层只能改最小开放字段；派生字段和真值字段必须分清；冷却剩余时间是由 `last_limit_time` 派生的可编辑输入，只有用户实际改动输入框才允许覆盖；网页修改必须按当前 `db_mode` 回写对应 canonical 并回读确认；`临时号` 只读展示，不参与 1-8 执行位健康检查。

## `web_view_server.py`

- 负责什么：本地网页服务、HTTP 路由、页面入口、表单提交入口、远端同步相关入口。
- 不负责什么：不负责具体 SQL 拼装，不负责模板细节。
- 改它要小心什么：这里定义了哪些入口对外开放；当前公网写回入口默认关闭，不要在文档里写成已开放。

## `web_view_templates.py` / `web_view_templates_inventory.py`

- 负责什么：网页模板、页面片段、表格渲染、样式和库存语义版页面展示。
- 不负责什么：不负责真源判定，不负责数据库读写。
- 改它要小心什么：模板能改展示，但不应偷偷改业务语义；页面文案不能误导用户把镜像当真源。

## `local_switch_account_config.py`

- 负责什么：真实本机换号配置读取、上架价格读取、昵称模板目录/区域/阈值适配。
- 不负责什么：不负责保存示例文件，不负责主业务流程。
- 改它要小心什么：真实文件优先、示例文件只说明结构；不同电脑差异优先在这里解耦。

## `live_paths.py`

- 负责什么：把 `C:\py666` 作为 live 根目录优先解析，并记录命中的真实路径来源。
- 不负责什么：不负责业务逻辑，不负责数据库写回。
- 改它要小心什么：这是“当前到底命中了哪份 live 数据”的总入口；改错会让所有模块读错源。

## `machine_sync_config.py`

- 负责什么：本机网页同步配置读取，解析 `sync_enabled`、`receive_remote_sync`、`receive_remote_writeback`、绑定地址等。
- 不负责什么：不负责实际镜像存储和远端请求。
- 改它要小心什么：这里的布尔开关直接影响网页服务暴露范围和远端同步行为。

## `remote_sync.py`

- 负责什么：最小快照构建、远端镜像库写入、手动刷新、远端最小写回代理逻辑；本机快照会带上 `临时号` 辅助快照行。
- 不负责什么：不负责 canonical 主表结构。
- 改它要小心什么：镜像不是 canonical；允许代理发起写回，不等于允许把镜像层升级成真源。
