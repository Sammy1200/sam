# 执行位调度、切区与换号

这份文档用于解释当前系统怎么做执行位调度、同账号切区、跨账号换号、昵称校验和失败治理。重点是“现在怎么工作”，不是历史怎么演变到今天。

## 执行位是什么

当前系统以执行位组织主流程：

- 默认执行位数量是 8
- 每个执行位会映射到一个大区索引
- 4 个大区坐标在 `config.SERVER_COORDS`
- 执行位到大区的映射在 `config.EXECUTION_SLOT_SERVER_COORD_INDEXES`

执行位主要用于：

- 启动器识别后自动定位当前账号上下文
- 解析下一跳调度目标
- 在网页和悬浮窗中定位当前账号所在流程位置

## 默认模式的启动调度

默认回车启动时，系统做的是：

1. 从启动器画面识别当前执行位
2. 先把这个执行位作为昵称提示，去 canonical 读取账号记录
3. 如果昵称本身是数字或未直接命中，会按执行位兼容读取
4. 读到 canonical 记录后，得到真实昵称和当前执行位
5. 再按执行位自动推出目标大区
6. 沿启动器链进入游戏和交易行

所以默认模式不是人工选账号，而是“识别执行位 -> 读库 -> 推出账号上下文 -> 自动进链路”。

## 调度如何决定“切区”还是“换号”

当前调度逻辑按执行位边界区分两类情况：

- 非边界切换：同账号内跨区切换
- 边界切换：跨账号换号

当前固定边界是：

- `4 -> 5`
- `8 -> 1`

当命中边界时，系统会走换号链；否则只走同账号跨区链。

## 当前已落地主体能力

当前主线已经落地的主体能力包括：

- 启动器识别执行位
- 按执行位和昵称读取 canonical 账号记录
- 同账号跨区切换
- 跨账号换号
- 换号后昵称模板校验
- 换号成功后把账号状态写成 `运行中`
- 换号后先完整上架，再进入抢购
- 换号后清零跨账号残留计数器
- 关键失败出口统一暂停并推送

## 换号链的本机配置入口

换号所需的本机差异不直接硬编码在主业务里，而是从本机配置层读取，主要包括：

- 边界换号使用的真实账号 ID
- 上架价格
- 昵称模板目录
- 昵称识别区域
- 昵称匹配阈值

因此处理换号问题时，先区分是：

- 本机配置问题
- 还是主流程逻辑问题

## 昵称校验怎么工作

昵称校验当前依赖：

- 模板目录
- 本机识别区域
- 本机匹配阈值

这些值通过 `local_switch_account_config.py` 从真实本机配置加载。当前设计目的是：

- 不把不同电脑的显示差异硬编码到主线逻辑
- 让模板、区域、阈值跟着本机环境走

## 失败治理怎么收束

当前切换链的失败治理不是“简单返回 False”，而是统一走失败出口：

- 记录中文日志
- 推送消息
- 暂停脚本
- 尽量保留现场，等待人工确认

这意味着：

- 切换问题先看失败步骤名
- 再看对应等待参数、模板、坐标、本机配置

## 当前已知可接受风险

- 这条链路对 UI 模板、坐标和等待参数高度敏感。
- 本机模板资源和识别区域不一致时，容易出现“逻辑没坏，但本机识别失败”的问题。
- 执行位种子记录只是建档兜底，不应误认为真实账号资料。

## 明确未纳入范围

- 不把换号后“先上架再抢购”的顺序改掉。
- 不把步骤 6-8 随意重排。
- 不把昵称模板校验替换成任意别的主键语义。
- 不把临时模式重新接回 canonical 单账号主表写回。
