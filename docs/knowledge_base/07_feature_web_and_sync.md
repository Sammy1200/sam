# 网页、本机查看与同步边界

这份文档用于解释网页层、本机查看、最小修改、远端镜像、公网快照当前分别处在什么边界。

## 当前已经落地的内容

当前主线已经稳定落地的网页能力包括：

- 本机 canonical 账号查看页
- 单账号最小修改
- runtime 辅助快照展示
- 本机机器级汇总展示
- `main.py` 自动检查并静默拉起网页服务
- 多机镜像展示与手动刷新，当前 1 号电脑按 `expected_remote_machines` 预置显示 2/3/4 号电脑
- 公网快照页查看与刷新按钮

其中“单账号最小修改”当前只允许 3 个字段：

- `baseline_item_count`
- `round_status`
- `current_balance_wan`

## 网页层当前只到查看 / 最小修改层

网页层当前的设计目标是：

- 快速查看 canonical 当前状态
- 做少量人工纠偏
- 做源与快照诊断

它不是：

- 全量后台
- 通用管理后台
- 任意字段编辑器
- 真源替代层

## 三层边界必须分开理解

### 1. 本机网页查看 / 最小修改

这是当前唯一允许修改账号数据的网页层入口，且只允许最小修改 3 个字段：

- `baseline_item_count`
- `round_status`
- `current_balance_wan`

修改后必须回写 canonical，并回读确认。

### 2. 远端镜像

远端镜像用于：

- 展示
- 汇总
- 手动刷新

远端镜像不是 canonical，也不是最终写入口。

### 3. 公网快照

公网快照当前正式口径只有两件事：

- 路由入口是 `/public-snapshot`
- 只查看
- 只开放“刷新按钮”

除刷新按钮外，公网不开放任何其他修改能力。

## 为什么网页不能当真源

当前网页写入实际是这样收口的：

- 表单提交给 `account_view_repo.py`
- 拼成最小写入
- 回写 canonical SQLite
- 立即回读校验

也就是说：

- 真正生效的是 canonical 写库成功后的结果
- 页面只是发起入口
- 回读不一致就算失败

## runtime 快照与网页列表的关系

网页里同时会展示 canonical 和 runtime 辅助快照，但两者地位不同：

- canonical：主事实
- runtime 快照：当前进程正在跑什么的辅助信息

网页会用 runtime 快照做健康摘要和匹配诊断，但不会把它当成主真值覆盖 canonical。

## 远端镜像当前边界

远端镜像当前可以做：

- 查看
- 汇总
- 手动刷新
- 保留远端最近快照

远端镜像当前不能做：

- 替代本机 canonical
- 直接覆盖本机轮次统计
- 直接覆盖本机轻量落库结果
- 直接作为最终写入口

出现远端镜像与本机不一致时，以本机 canonical 为准。

## 历史写回口径如何理解

历史阶段里曾出现过“远端最小写回”的设计和部分代码结构，但当前正式口径已经收口：

- 不要把它写成当前公网开放能力
- 不要把公网页面理解成可改对端真源
- 当前对外统一口径就是：公网只查看，并且只开放刷新按钮

## 当前明确不做或暂不做

- 双向同步
- 共享 SQLite
- 公网除刷新按钮外的任何修改
- 镜像层直接改真源
- 把公网快照升级为正式运维入口

## 公网快照为什么更不能当真源

公网快照额外多了网络、镜像和刷新时差问题，所以它的职责应更保守：

- 对外展示
- 只读参考
- 快照查看
- 手动刷新

而不是：

- 最终判定
- 远端调度主入口
- 真源替代物
